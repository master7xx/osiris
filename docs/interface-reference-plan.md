# Интерфейс OSIRIS по визуальному референсу

Статус: проект спецификации, не реализованный интерфейс.
Основа аудита: `master`, коммит `115b090` после PR #30.
Референс: предоставленное пользователем изображение с ночной картой,
левым меню, правой SIGINT-лентой и открытой панелью DEBUG.
Изображение задаёт композицию и стиль; его показатели, источники и пункты меню
не считаются требованиями добавить отсутствующую функциональность.

## 1. Первый экран

Центральная карта, слева навигация, справа World Events, сверху компактная
панель UTC/состояния данных, снизу координаты и масштаб. DEBUG закрыт при первом
открытии. Поиск постоянно доступен над картой. Инструменты открываются по запросу.

Предлагаемые размеры — начальные значения для визуальной проверки:

| Область | Большой экран, ширина от 1440 px | Ноутбук, 1024–1439 px |
| --- | --- | --- |
| Верхняя панель | 56 px | 56 px |
| Левое меню | 208 px, сворачивается до 56 px | По умолчанию 56 px; раскрывается по кнопке |
| Правая лента | 352 px, может быть скрыта | 320 px, может быть скрыта |
| Нижняя строка | 28 px | 28 px |
| Карта | Всё оставшееся пространство | Всё оставшееся пространство |
| DEBUG | В пределах карты, высота до 45% её области | Изменяемый размер, доступное сворачивание |

При ширине менее 1024 px меню и лента становятся выдвижными панелями;
одновременно открывается одна. Существующую мобильную навигацию сохраняем
до переноса каждого инструмента. Смена ориентации не должна сбрасывать слои.
При раскрытии панелей карта получает новую область отображения и resize.

## 2. Состав меню и соответствие коду

| Раздел | Пункты первого этапа | Действующая реализация / действие |
| --- | --- | --- |
| Обзор | World Events | Видимость общего слоя; управление сейчас внутри `BreakingNewsMarkers.tsx` |
| Авиация | Commercial, Private, Private Jets, Military | Ключи `flights`, `private`, `jets`, `military`; группировка без удаления переключателей |
| Море | Maritime / Naval | Действующий объединённый ключ `maritime`; не создавать фиктивные независимые переключатели Vessels/Ports/AIS |
| Космос | All Satellites; Comms, Military, Navigation, Earth Observation, Science | Существующие `satellites` и `sat_*`; подгруппу можно свернуть |
| Наблюдение | CCTV, Live Previews, Live News Feeds | `cctv`, `cctv_previews`, `live_news`; превью зависят от родительского слоя |
| Природные события | Earthquakes, Active Fires, Severe Weather | `earthquakes`, `fires`, `weather` |
| События и инфраструктура | Global Incidents, GDELT Events, Nuclear Facilities | `global_incidents`, `gdelt_events`, `infrastructure`; обозначить как специализированные слои |
| Сеть | Malware, Cyber visualization; Radar outages/origins при настройке | Существующие `malware`, `cyber_attacks`, `cf_outages`, `cf_attacks`; сохранить ограничения возможностей |
| Интеграции | SDK Maritime Lines | Существующий `sdk_sea`; не удалять из-за отсутствия в референсе |
| Инструменты | RECON, Markets, Live Alerts, Draw/AOI, Directions, ArcGIS, Space video | Перенести существующие действия правой полосы без изменения их данных |
| Дополнительные инструменты | BLE/World Remote, Share, View Presets, Flight Watch | Сохранить доступность существующих сценариев; не обязательно показывать все пункты постоянно |
| Отображение | Day/Night, Terrain, Style Studio, Ghost mode | Существующие слои и настройки; сохранить пользовательскую тему |
| Система | DEBUG, Shortcuts | Существующая диагностика и справка по клавишам |

Airfields, Launches, Debris, ISR Feeds, Social Media и Web Monitoring из картинки
не добавляются как отдельные новые инструменты в этом этапе. Sanctions остаётся
внутри RECON, пока для него нет отдельного сценария навигации. Кнопка Home может
закрыть дополнительные панели, но не должна сбрасывать выбранные слои или AOI.

Наличие кода само по себе не делает источник достоверным: `cyber_attacks` содержит
синтетические смещения и подписи. Его нельзя обозначать как подтверждённые живые
атаки или использовать в качестве доказательств World Events. Сохранение старого
инструмента не означает подключение его вывода к единой ленте.

## 3. Лента, карта и карточка

Название основной правой панели — **World Events**. Текущий `IntelFeed.tsx`
самостоятельно опрашивает `/api/news`, а карта — `/api/events`; их необходимо
перевести на один клиентский снимок и общий выбранный ID события.
`showIntel` в `page.tsx` управляет RECON: не переиспользовать его как флаг ленты.

Предлагаемые состояния: `selectedEventId`, `eventFilters`, `activeTool`,
`navigationExpanded`, `eventFeedOpen`, плюс существующее состояние слоёв.
Первый этап не меняет названия ключей слоёв в URL и сохранённые настройки.
Видимость World Events переносится из локального состояния маркеров в общий
контроллер с чтением существующего `osiris.world-events-visible`.

Правила взаимодействия:

- Выбор карточки выделяет соответствующий маркер; выбор маркера открывает карточку.
- Автоматическое обновление сохраняет выбранное событие по стабильному ID.
- Событие без координат остаётся в списке; действие «показать на карте» недоступно.
- При исчезновении события из текущего снимка показать это явно, не выбирать другое молча.
- Видимые фильтры применяются к общему клиентскому набору данных. Список может
  содержать немаппируемые события; подпись счётчика разделяет «в ленте» и «на карте».
- Первый вариант: категория, серьёзность, подтверждение, «только на карте».
  Фильтры Breaking/Regional из картинки не добавлять без определения их смысла.
- В карточке: заголовок, категория, время события UTC и относительный возраст,
  серьёзность, подтверждение, местоположение/уверенность и ссылки на свидетельства.
- Severity и confidence показываются отдельно. Не подменять их единым HIGH/MED.
- Изображения необязательны: `ContinuousEvent` не гарантирует миниатюру.
- Пока журнал не постоянный, клиент использует снимки. Не обещать восстановление
  истории по курсору после перезапуска или непрерывную доставку всех событий.

## 4. Стиль и диагностика

Предлагаемая палитра оболочки: фон `#06101a`, панели `#091724`, текст `#dceaf7`,
акцент `#00b7ff`, линии `#18384e`. Цвета опасности сохраняют отдельный смысл.
Свечение использовать для выбранного события и активных действий, не для всех
границ. Основной текст 13–14 px; моноширинный шрифт — время, координаты, диагностика.
Существующие настройки Style Studio не перезаписывать при загрузке нового каркаса.

Состояния данных: загрузка, свежий снимок, частичная доступность, устаревший снимок,
ошибка без данных, пустая выдача. Надпись «все системы исправны» не выводится по
успеху одного `/api/health`. Возраст снимка показывается независимо от здоровья
источников в момент последнего успешного сбора.

DEBUG сохраняет текущие корреляции и очищенный экспорт. Новый вид включает
сворачивание, ограниченное областью экрана изменение размера и прокрутку таблицы.
Вне открытой панели её прозрачная область не перехватывает управление картой.
На узком экране диагностика открывается отдельной панелью. Управление доступно
с клавиатуры; Escape закрывает верхнюю панель, фокус возвращается к её кнопке.
Анимации учитывают prefers-reduced-motion.

Ночная карта требует проверки существующих стилей и доступных тайлов. Огни городов
и дуги на референсе не означают наличие спутникового ночного снимка или реальных
связей. Такие данные не генерируются для украшения карты.

## 5. Последовательность реализации

| Этап | Содержание | Критерий завершения |
| --- | --- | --- |
| A — Каркас | Выделить оболочку из `page.tsx`; меню на основе текущих групп, header, dock ленты, размеры и сворачивание | Все прежние инструменты доступны, панели не перекрывают управление, настройки/URL сохранены |
| B — События | Общий клиентский снимок `/api/events`, новая лента, выбор ID, карточки и фильтры | Выбор работает в обе стороны; координаты и состояние события не расходятся между списком и картой |
| C — Доводка | DEBUG, состояния сбоев, доступность, адаптация и визуальная проверка | Клавиатура/фокус работают, нет ложного LIVE, нет переполнения на проверенных размерах |

В A правый dock может временно содержать текущую новостную панель с честным
названием News; полноценное название World Events вводится вместе с общим
источником в B. Не выпускать две панели с одинаковым названием и разными данными.
Изменения README входят в каждый этап. Постоянное хранилище и фоновый сбор —
отдельные серверные работы, не скрытые зависимости базового оформления.

## 6. Проверка

Проверять 1920×1080, 1440×900, 1366×768, 1024×768 и 390×844; отдельно масштаб
браузера 200%, клавиатуру, reduced motion и восстановление сохранённых настроек.
Использовать реальные данные при доступности, явно обозначенные тестовые фикстуры
для воспроизводимых состояний. Не считать скриншот доказательством доступности API.

Проверки логики нужны для миграции настроек, фильтрации и синхронизации выбора.
Проверки браузером — для геометрии карты, открытия/закрытия панелей, фокуса и
сохранения выбранного события при обновлении. Не создавать тесты, которые только
дублируют CSS или проверяют наличие текста. Windows CI: tests, build, smoke.

Предварительный бюджет A–C: 5–8 рабочих дней одного разработчика с Codex,
с уточнением после визуальной проверки этапа A. Это трудозатраты, не календарное
обещание и не утверждение о фоновой работе. Сроки постоянного хранения сюда не входят.
